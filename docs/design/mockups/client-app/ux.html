桌面客户端原型 · 交互说明

这份说明对应同目录下的可点击原型。功能来自对现有代码的盘点（见 INVENTORY.md），视觉沿用网站原型的方向。每个界面和状态都有独立地址，下文的链接直接打开对应状态。

从首次启动开始直接进入「发现」English

原型右下角的「原型控制」不属于产品：切换登录状态、Free / Pro、检测到的 agent、窗口控件样式、窗口尺寸、语言、项目（示例项目 / 一个都没有）、目录在线 / 离线，模拟网页安装链接，以及重置。状态存在浏览器的 sessionStorage 里，关掉标签页即清空。

二、流程

1. 首次启动

  1. 检测 agentClaude Code、Codex 各一行：已检测到 / 未检测到；末尾一行「更多即将支持」。打开
  2. 迁移结果只在发现旧目录 ~/.agents 时出现，是报告，不需要用户选择。打开
  3. 准备就绪三条提示，进入「发现」。打开
  4. 一个 agent 都没有给出说明，仍可继续浏览。在原型控制里把「检测到的 agent」切到「都没有」后重新走一遍。

2. 发现与安装

  1. 搜索输入即筛选，250ms 防抖，请求期间显示骨架。搜 flow
  2. 详情基本信息、安装时写入的内容、命令行写法、说明节选。打开
  3. 选 agent默认勾选所有能用的；不能用的置灰并写明原因。打开
  4. 填必填项只有需要时出现；可「稍后填写」，此时装上但不启用。
  5. 进度逐步显示写到哪个文件；进行中不能关闭。
  6. 完成列出每个 agent 的结果；「查看」或「打开配置」。
  7. 同名 MCP 条目冲突暂停，选择「跳过这个 agent」或「替换现有条目」。用 Front-End Checklist 试
  8. 目录取不到安装失败，说明没有装任何内容，可重试。先在原型控制里切到「离线」。

3. 从网页安装

  1. 链接到达agent-store://install?id=… 在任何界面上弹出确认框，焦点落在「取消」。技能 · 需要令牌的 MCP · 供应商
  2. 确认与应用内安装是同一个对话框，多一条「由网页链接发起」的提醒。
  3. 之后同流程 2 的第 4 至 6 步。
  4. 已经安装过了提示，带「查看」。打开
  5. 没有找到打开
  6. 链接无法识别打开
  7. 类别不一致打开
  8. 只有 SSECodex 一行置灰并写明原因。打开

4. 技能库

  1. 列表每行两个开关，对应两个 agent；表头留一格「更多即将支持」。打开
  2. 启用 / 停用点开关即生效，底部提示结果，状态栏记一行命令。
  3. 详情每个 agent 的链接位置、技能库路径（复制、在文件管理器中显示）、版本。打开
  4. 更新单项「更新」或表头「全部更新」。
  5. 卸载先确认，列出会删除什么。打开
  6. 同名内容不是 Agent Store 放的对 grill-me 打开 Codex 开关：拒绝，可「强制启用」。
  7. 本地改过卸载 find-skills：普通卸载失败，可「强制卸载」。打开

5. MCP

  1. 列表运行方式标记（npx / uvx / docker / 远程 / 远程 SSE），每个 agent 一个开关。打开
  2. 配置必填项带 *，输入即自动保存，密钥默认遮蔽。打开
  3. 写到哪里每个 agent 一行，写明配置文件和键名。
  4. 在 Agent Store 之外被改过对 Netdata 关闭 Claude Code 开关：拒绝修改；卸载时可强制。打开

6. 供应商与本地中转

  1. 总览中转状态、每个 agent 的转发链、按优先级排列的供应商。打开
  2. 调整顺序上移 / 下移，Level 数字随之改写。
  3. 编辑配置名称、密钥、更多设置（地址、端点、协议、认证、优先级）、高级（白名单、映射、可用性监控）。打开
  4. 再添加一份配置同一供应商的第二个账号。
  5. 请求日志最近请求与降级标记。打开
  6. 缺少密钥对 YLS 打开开关：提示先填密钥，焦点落到密钥框。打开
  7. Free 与 ProFree 每个 agent 最多用前 2 个上游；Pro 显示供应商健康、多 Key。在原型控制里切换方案。

7. 用量

  1. 趋势与汇总今日 / 近 7 天 / 近 30 天。打开
  2. 明细按供应商、模型、agent。
  3. 预算与导出Pro 功能；Free 显示说明和升级入口。
  4. 没有数据打开

8. 账号

  1. 未登录侧栏底部的账号按钮，菜单里是「登录」。
  2. 选择方式GitHub 或 Google。打开
  3. 等待浏览器登录在系统浏览器里完成；可重新打开、可取消。打开
  4. 已登录菜单显示邮箱、方案、升级或管理订阅、退出。
  5. 升级打开网站的定价页，客户端内不结账。方案说明

9. 项目 提案，现有客户端没有

项目级的技能和 MCP 写在项目目录内，随版本库提交：技能写入 <项目>/.claude/skills（Claude Code）和 <项目>/.agents/skills（Codex），MCP 写入项目根的 .mcp.json（目前只对 Claude Code）。同名时项目覆盖全局。密钥的值只存在本机：.mcp.json 里只写变量引用（如 ${CONTEXT7_API_KEY}）。模型服务商没有项目级。

  1. 侧栏分组「项目」下列出已登记的项目和条目数，末尾「添加项目」；目录不存在的项目带警示图标。窄窗口收成一个图标，进入项目列表。打开
  2. 添加项目选择目录（原型用预设路径和输入框代替系统的目录选择框）。添加只是登记，不改动目录里的文件。在列表页点「添加项目」
  3. 项目页页头是名称、路径、「添加到这个项目」「在文件管理器中显示」「移除项目」；下面分技能、MCP 两个区块。每行写明对哪些 agent 生效、写在哪里、来源。打开
  4. 来源「由 Agent Store 安装」的可以卸载；「项目自带」的只读，只能在文件管理器中显示。
  5. 覆盖全局项目里的 MCP 与全局同名时带「覆盖全局」标记，悬停有说明，点开在行下展开说明并可跳到全局的那一条。Esc 收起。
  6. 缺少密钥队友提交了需要密钥的 MCP、本机还没填值时，行上显示「缺少密钥」，点开填写。值只存本机。示例里的 admux 是这种情形。
  7. 添加到这个项目进入「发现」，顶部提示正在为哪个项目挑选；安装对话框的安装位置已预选为这个项目。打开
  8. 安装位置安装对话框在选 agent 之前多一项：全局（默认）、某个已登记的项目、「添加项目…」。只对技能和 MCP 出现。选了项目时说明会随版本库提交、队友拉取后可用、Claude Code 首次使用项目里的 MCP 需要批准；MCP 的 Codex 一行置灰并写明原因。网页安装链接走同一个对话框。打开
  9. 填密钥必填项一步写明：.mcp.json 里只写变量引用，值存本机。可「稍后填写」，装完后在项目页显示「缺少密钥」。
  10. 完成写明装到了哪个项目、对哪些 agent 生效；主按钮「打开项目」跳到项目页。
  11. 卸载项目里的条目先确认，列出会删除或改动的文件，并提示改动需要提交后队友才会同步。
  12. 移除项目先确认。只是不再管理，不删除任何文件，可以随时重新添加。
  13. 重复登记同一目录不能登记两次，对话框里指出已有的那个项目并可直接打开。
  14. 目录不存在提示目录可能已移动、改名或删除，可「重新定位」或「移除项目」，其余操作禁用；下方保留最后一次读到的内容。打开
  15. 项目里已有同名条目安装位置里这个项目置灰，注明「已安装」或「已有同名条目」。

技能库和 MCP 页面只列全局安装的内容，页头有一行提示指向项目列表。技能 · MCP

五、需要拍板的问题

以下是我做原型时不得不假设的地方。代码里没有 表示这是新设计。

  1. 怎样算「检测到」一个 agent？ 代码里没有 现在引擎不做检测，找不到可执行文件时直接改配置文件。原型假设：配置目录存在或可执行文件在 PATH 里即算检测到；未检测到时开关置灰。要不要允许对未检测到的 agent 预先写配置？
  2. 安装前选 agent。 代码里没有 现在是一键装到所有兼容的 agent。原型加了一步选择，默认全选。引擎只支持单个 target，多选需要界面逐个调用。是保留这一步，还是维持一键、装完再关？
  3. MCP 冲突时的「替换现有条目」。 引擎和命令行已支持（--replace，停用或卸载时写回原条目），界面目前只让用户自己去改名或删除。原型给了按钮。文案里写了「替换前会保存原条目，停用或卸载时写回」，这句话要不要对用户承诺到这个程度？
  4. 卸载确认框。 代码里没有 现在点 × 立即卸载。原型加了确认，并列出会删什么。
  5. 供应商优先级的操作方式。 代码里是每个供应商一个 Level 数字（1–10），可以相同。原型用上移 / 下移，按新顺序把 Level 改写成 1、2、3…。这样会丢掉「两个供应商同级」的可能，是否可以接受？
  6. 在界面里启动 / 停止本地中转。 命令行有 aas relay start|stop，界面目前只显示状态。原型给了开关。
  7. 智能路由和多 Key 轮换。 客户端代码已实现并按 Pro 开放；网站定价页写的是「规划中」。原型按代码的现状做成 Pro 功能，两边需要统一说法。
  8. 「检查更新」的含义。 代码里检查的是已安装资源的新版本，客户端自身没有自动更新。原型把它命名为「资源更新」，客户端新版本给一个去官网的入口。要不要做客户端自动更新？
  9. 登录状态是否持久。 我读到的代码把会话放在内存里，重启后要重新登录（方案缓存在本机，不受影响）。这是有意的吗？原型没有表现重启。
  10. 主题。 现有代码有亮色主题切换；原型只做深色，设置里写明「当前只提供深色主题」。
  11. 收藏。 代码里收藏只存在内存中，也没有「我的收藏」列表。原型保留了收藏按钮，同样没有列表。要补一个筛选，还是去掉？
  12. verified 标记。 目录数据里有，含义我没有查实。为避免被读成安全审核结论，原型不显示。
  13. 密钥遮蔽。 代码里供应商密钥是明文输入框。原型默认遮蔽，带显示切换。
  14. 命令面板、全局快捷键、操作记录面板、技能库路径与「在文件管理器中显示」、用量明细表、「全部更新」按钮。 均为新设计；后三项的数据或命令在代码里已有。
  15. 首次启动引导。 代码里没有 迁移现在是无界面自动完成的。原型把结果展示出来，但不让用户选择。没有做「导入用户自己已有的技能或 MCP 配置」，因为引擎不支持接管没有标记的内容。
  16. 必填项的判断。 目录样本只标了「需要」哪些变量，没区分必填和选填。原型把它们都当必填。
  17. 登录后账号示例。 邮箱 lin@example.com、用量数字、请求日志、供应商健康里的冷却状态都是示例，界面上标了「示例数据」。

新增设计：项目（提案）

整个「项目」功能是提案，现有客户端和引擎都没有：侧栏分组、项目列表、项目页、添加 / 重新定位 / 移除项目、安装对话框里的「安装位置」、「覆盖全局」和「缺少密钥」标记。界面里的行为全部是模拟。

已定的规则。项目级内容一律进版本库，不区分私有和共享：技能写入 <项目>/.claude/skills（Claude Code）和 <项目>/.agents/skills（Codex）；MCP 写入项目根的 .mcp.json（Claude Code），队友拉取后首次使用需要批准。同名时项目覆盖全局。密钥只存本机，.mcp.json 里只写变量引用。模型服务商不做项目级。

第一期只做：登记项目、查看项目里的技能和 MCP（含不是 Agent Store 装的，只读）、安装时选择安装位置、覆盖全局的提示、缺少密钥的提示与填写、卸载由 Agent Store 安装的条目。

后续再做：项目内容与技能库的差异比对和双向同步；按项目停用某一条；命令行 aas projects 子命令。原型里没有这些入口。

  1. Codex 的项目级 MCP 是否支持？ 待核实 Codex 是否读取项目里的 .codex/config.toml。核实之前，项目级 MCP 只支持 Claude Code，安装对话框里 Codex 一行置灰并写明原因。
  2. 是否需要「只在本机、不进版本库」的项目级 MCP？ Claude Code 支持这种写法（记在 ~/.claude.json 里该项目名下）。当前不做，项目级 MCP 只有进版本库这一种。
  3. 密钥的值存在本机的什么位置，怎样交给 agent？ 原型只表现了「.mcp.json 写变量引用、值存本机、每人各填一次」，没有设计存放位置和注入方式。
  4. 拉取下来的条目怎样判断是不是 Agent Store 装的？ 队友用 Agent Store 装进项目、我拉取之后，本机没有安装记录。原型把这种条目显示为「项目自带」（只读）。要不要在项目里留标记，让它在每个人的机器上都能更新和卸载？
  5. 项目级技能没有更新入口。 技能文件直接写进项目目录，不链接到本机技能库。第一期不做差异比对，所以项目页不显示「可更新」；更新要等后续的同步功能。
  6. 项目里的条目没有详情栏。 项目页的行不能点开看版本来源、运行方式等详情，只有行内的操作。是否需要与全局条目一样的详情栏？
  7. 已经全局安装的条目怎样装进项目？ 「发现」里已安装的条目显示「管理」而不是「安装」，原型只在从项目页点「添加到这个项目」进入时才给出安装到项目的按钮。
  8. 添加项目时是否扫描目录。 原型里新添加的项目是空的；真实客户端应当读出目录里已有的技能和 .mcp.json。项目名取目录名，原型没有做改名。
  9. 技能同名时的优先级没有查实。 「覆盖全局」标记目前只对 MCP 显示；项目级技能与全局技能同名时 agent 用哪一个，需要对照两个 agent 的文档后再决定是否显示。
